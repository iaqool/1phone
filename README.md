# OnePhone

Модуль допуска для кампаний Torque по проверенному Seeker Genesis Token (SGT). OnePhone регистрирует один допуск на SGT mint в конкретной кампании и готовит список получателей. Это не доказательство уникальности человека.

Текущее состояние: локальное ядро и экспорт для Torque собраны и проверены — 10 unit-тестов и 10 транзакционных сценариев (TAP 11/11 с родительским test). Android-клиент собран до Hermes bundle, но APK и настоящий Seeker ещё не проверены. Живое подключение Torque также впереди. Результаты и следующий шаг — в [STATE.md](STATE.md).

Для Colosseum подготовлены [английский черновик заявки](docs/SUBMISSION.md) и [квадратный логотип](docs/onephone-logo.png). Заявка ещё не отправлена.

Локальные данные для инструментов хранятся в `.env.local` по именам из `.env.example`; оба файла находятся в корне OnePhone, но только пример попадает в Git. Заполнять файл в локальном редакторе, без передачи секретов в чат. Файл не подгружается автоматически: при конкретной операции считываются только нужные переменные. Для GitHub предпочтителен `gh auth login` с системным хранилищем; `GH_TOKEN` нужен лишь как альтернативный ограниченный токен. Мобильный `mobile/.env.local` содержит только публичные `EXPO_PUBLIC_*`, которые Expo встраивает в APK. Seed-фразу, приватные ключи и cookie Colosseum нигде в проекте не сохранять.

## Модуль для Torque

`register_namespace` создаёт неизменяемую область кампании с deadline. `consume` проверяет текущего владельца SGT и записывает допуск без выплаты; повторная регистрация того же mint блокируется программой, включая конкурентные заявки. После завершения окна read-only экспортёр готовит JSON для Torque `direct` incentive с одной эпохой и `confirmed: false`.

Экспортёр не вызывает Torque. Повторное административное создание incentive с тем же списком может привести к повторной внешней выплате; атомарной гарантии `consume + Torque payout` пока нет. Старый локальный сценарий `init_campaign`/`claim`/`close_campaign` с собственным reward vault сохранён и проверяется отдельно.

Контракт, официальные источники и команда экспорта — в [docs/TORQUE-INTEGRATION.md](docs/TORQUE-INTEGRATION.md). Полный локальный тест сохраняет синтетический пример в `.local/torque-preview.json`; это не реальная кампания и не ответ сервиса Torque.

## Android-клиент

В [mobile/README.md](mobile/README.md) — установка, запуск development build и публичная конфигурация развёрнутой кампании. Один экран подключает кошелёк через MWA, проверяет реальный SGT на mainnet, показывает состояние кампании и отправляет `consume` только для подтверждённого допуска. Он использует те же исходники SGT-проверки и построения инструкции, что и локальные тесты. Без адреса развёрнутой программы регистрация отключена; синтетический локальный program ID не используется как mainnet-развёртывание.

## Проверка SGT без транзакций

Проверено с Node.js 22.22.2 и npm 10.9.8. Из этой папки:

```powershell
npm ci
npm run typecheck
npm test
npm run sgt -- PUBLIC_SOLANA_WALLET_ADDRESS
```

Последняя команда только читает mainnet. Вместо `PUBLIC_SOLANA_WALLET_ADDRESS` подставить публичный адрес. При необходимости RPC задаётся переменной окружения `SOLANA_RPC_URL`; ключи и seed-фраза не нужны. Ответ содержит `hasSGT` и `mintAddress`. Ошибка RPC возвращает ненулевой код, а не отсутствие SGT.

Проверяются Token-2022, mint authority, metadata pointer authority/address, token group и связь member с mint. Для владения проверяются программа token account, владелец, инициализация и баланс ровно 1. Frozen account допустим. Пустой счёт после переноса токена не подходит.

Официальный источник констант и правил: [Solana Mobile — SGT verification](https://github.com/solana-mobile/solana-mobile-skills/blob/main/skills/seeker-genesis-token/references/sgt-verification.md).

## Локальная программа

Сборка и Solana validator работают в Docker Desktop (Linux containers). Windows-установка Rust/Anchor/Solana не требуется. Образ `solanafoundation/anchor:v0.32.1` закреплён digest в скрипте. Для SBF подключаются platform-tools v1.56 (Rust 1.89), поскольку встроенная v1.48 не поддерживает Rust edition 2024 некоторых зависимостей. Артефакт собирается для v0 и Cargo.lock проверяется через `--locked`. Фактический статус указан в `STATE.md`.

```powershell
./scripts/solana.ps1 doctor
./scripts/solana.ps1 build
./scripts/test-local.ps1
```

`test-local.ps1` собирает программу, генерирует fixtures, запускает validator, ждёт готовности, выполняет тесты и останавливает созданный контейнер. Для ручного запуска: `npm run setup:local`, `./scripts/solana.ps1 start`, `npm run test:local`, `./scripts/solana.ps1 stop`. Не регенерировать fixtures при работающем validator: он читает их только при старте.

Локальный RPC доступен только на `http://127.0.0.1:18999`, WebSocket — `ws://127.0.0.1:19000`. Скрипт `stop` останавливает только контейнер `onephone-local-validator`. Локальный ledger временный: остановка контейнера удаляет его тестовую историю. Кэш crates и SBF-компилятора сохраняется в отдельных Docker volumes с префиксом `onephone-`, артефакт — в `target/deploy/onephone.so`.

Тестовые SGT создаются инъекцией синтетических аккаунтов в локальный validator. Они не являются настоящими Seeker-токенами. Production-константы и проверки программы для тестов не подменяются. В mainnet тесты не отправляют транзакции.

Сценарий с другим владельцем использует искусственные счета одного mint. Он проверяет ключ receipt; настоящий перенос SGT между кошельками на устройстве ещё не проверялся. Временные тестовые ключи генерируются в `.local`, не выводятся в консоль и исключены из Git.

`program-id.txt` содержит публичный идентификатор для локальной загрузки `.so`. Ключ для развёртывания под этим адресом не сохранялся. Перед любым внешним развёртыванием нужно отдельно создать deployment keypair, согласованно обновить ID и проверить конфигурацию; текущее ядро не развёрнуто в mainnet.

## Работа в Codex

Основной исполнитель — Sol/medium; узкие вспомогательные задачи — Luna/high; критическое ревью — Astra/high. Максимум один активный подагент. Текущие задачи и ограничения — в `TASKS.md`, `STATE.md` и `AGENTS.md`.

Публичный адрес Seeker Димы ожидается позже. До него можно завершать локальные проверки; проверка настоящего SGT и Android/MWA остаются отдельными этапами.
